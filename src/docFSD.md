## Основная концепция

### Это первый уровень, и называется он "Слои"

<u>Слои должны следовать в определённой последовательности друг за другом:</u>

> 1. **App** - Всё, благодаря чему приложение запускается (роутинг, точки входа, глобальные стили, state manager). Это экосистема, благодаря которой приложение в целом функционирует.

> 2. **~~Processes~~** - Устаревший слой, который сейчас редко используется. В относительно старых проектах служил для сложных межстраничных сценариев (например, перевод денег в онлайн-банке: выбор счета → указание получателя → подтверждение через СМС). В новом подходе такая функциональность реализуется через связку фич в Features.

> 3. **Pages** - Полные страницы или крупные разделы страниц при вложенном роутинге (например: профиль пользователя, регистрация, авторизация - если они реализованы как отдельные страницы).  
>    **ВАЖНО**: Pages - это не целый компонент страницы, а скорее **КОНТЕЙНЕР ДЛЯ ВИДЖЕТОВ**, который собирает внутри себя необходимые для конкретной страницы элементы. Например, страница заказа билетов может включать виджет поиска билетов и список найденных вариантов.

> 4. **Widgets** - Виджеты, из которых состоит конкретная страница (Page). Они реализуют целые пользовательские сценарии и представляют собой крупные UI-блоки.  
>    **Примеры**:

- CartWidget - показывает количество билетов в корзине и кнопку "Оформить заказ"
- UserProfileCard - карточка профиля с аватаркой и кнопкой "Редактировать"
- Элементы пагинации

> 5. **Features** - Основные функциональные модули проекта. Если проводить аналогию с автомобилем: двери, окна и кондиционер - это виджеты (без них машина поедет), а двигатель и коробка передач - это Features (без них машина не поедет).

> 6. **Entities (сущности)** - Бизнес-сущности, с которыми работает проект. В нашем примере - это карточка билета, которая может состоять из различных виджетов.

> 7. **Shared** - Переиспользуемый код, особенно когда он не привязан к бизнес-логике проекта. Здесь находятся базовые UI-компоненты (кнопки, чекбоксы и т.д.), из которых состоят виджеты и сущности. Логика добавляется на уровне их использования.

<u>**Почему слои идут в такой последовательности и пронумерованы?**  
**Не просто так!** Главная особенность слоёв в том, что модули на одном уровне могут знать только о модулях с нижележащих слоёв и, соответственно, импортировать только их. (Хотя могут быть исключения!)</u>

## Частые проблемы

### Частая путаница: куда помещать компоненты

| Что?                  | Куда?               | Пример                          |
| --------------------- | ------------------- | ------------------------------- |
| Кнопка, инпут         | shared/ui           | shared/ui/Button                |
| Карточка билета       | entities/ticket/ui  | entities/ticket/ui/TicketCard   |
| Форма бронирования    | features/booking/ui | features/booking/ui/BookingForm |
| Страница бронирования | pages/BookingPage   | pages/BookingPage/index.tsx     |

---

## Как проверить

### Как проверить, что слои не нарушены?

1. **Может ли этот модуль работать без вышестоящих слоёв?**  
   Например, entities/Ticket должен функционировать даже без pages.

2. **Где используется эта логика?**
   - Если только на одной странице - вероятно, это widget
   - Если в трёх и более местах - скорее всего, feature

3. **Чем ниже слой по иерархии, тем чаще он может переиспользоваться**

## Идеальное представление слоя

> P.S. Тут всё представлено в виде примеров, в реальности может отличаться

**App**  
Не имеет слайсов и состоит из сегментов напрямую.

**Pages (Страницы-контейнеры для Widgets)**

- Pages - Home - ui (интерфейс), model (локальный стейт страницы, если он есть)
- Pages - Registration - ui, model
- Pages - UserProfile - ui, model

**Widgets (Комплексные UI-блоки)**

- Widgets - Ticket - ui (вёрстка), model (логика тикета. БЕЗ API)
- Widgets - Header - ui, model
- Widgets - AuthModal - ui, model

**Features (Бизнес-фичи)**

- Features - auth - api (запросы к серверу), model (логика - хранилище, валидация), ui (формы, кнопки - если уникальные)
- Features - order - api (запрос к серверу на бронирование билета), model (логика бронирования)

**Entities (Бизнес-сущности)**

- Entities - user - api, model, ui

**Shared (Общие ресурсы)**  
Не имеет слайсов и состоит из сегментов напрямую.

- Shared - ui
